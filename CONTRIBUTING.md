# Contributing

## Good additions

- Clearer stage explanations in the README
- Alternative skeletons (e.g. async tools, file-backed transcript)
- Short postmortems: `I built a harness and learned X`
- Links to high-quality primary learning resources

## Not welcome

- Guides aimed at unauthorized access, abuse, or harm
- Pasting large copyrighted tutorials
- Framework marketing dumps without a from-scratch lesson

## Tone

Small enough to read. Hard enough to matter.
